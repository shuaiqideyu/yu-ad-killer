# 检测触发时机与消息清理

## 检测触发时机

机器人在以下时机对群成员做违规检测：

| 时机 | 入口 | 检测内容 |
| --- | --- | --- |
| 进群（加入群组系统消息） | `handleNewChatMembers → checkJoinedMember` | 昵称(+用户名/语言/俄罗斯元素)、简介（关键词 + 俄语/地区/商家地址，强制刷新） |
| 进群（chat_member 更新） | `HandleChatMemberUpdated → checkJoinedMember` | 昵称(+用户名/语言/俄罗斯元素)、简介（关键词 + 俄语/地区/商家地址，强制刷新） |
| 群内发消息 | `HandleMessage → handleContactMessage` / `DetectorManager.CheckAll` | 名片（自己的/别人的/仅电话/Telegram 账号/vCard 文件）、并发转发、频道回复、昵称(+用户名/语言/俄罗斯元素)、简介（关键词 + 俄语/地区/商家地址）、消息关键词、消息里的邀请链接群名（英文不区分大小写与全角，中文不区分简繁；兼容字能折则折） |
| 群内编辑消息 | `edited_message → HandleMessage` | 同上（防先发干净内容再改成广告） |

进群即检测的目的：换号进群的广告号若昵称/简介已含关键词，无需等其发出第一条消息即可拦截，减少广告在群内的潜伏时间。

### 进群方式的全覆盖

两个进群入口配合，覆盖各种进群方式：

- **加入群组系统消息**（`new_chat_members`）：随普通消息推送，常见的主动加群、被邀请加群会产生。
- **chat_member 更新**：覆盖邀请链接、管理员审批、加入请求通过等**不产生系统消息**的进群方式。
  - 需要机器人是群管理员，Telegram 才会推送该更新。
  - 需要在 `getUpdates` 的 `allowed_updates` 中显式声明 `chat_member` 与 `edited_message`（见 `runtime.go` 的 `Start`）。一旦显式设置 `allowed_updates`，就只推送列出的类型，因此 `message`、`callback_query` 也一并列出。

### 工作群通知与自毁

- 管理员在业务群执行 `/lh` `/f` `/jy` `/t` `/unlh` 后，会向绑定的工作群发送通知：操作人、目标用户、原因/时长；若为引用回复，额外附带原文内容。
- 播报频道的封禁通知也会附带原文（若有）。
- 工作群内仅机器人自己发出的消息在发送后 24 小时自毁；管理员与其他成员发言不删除。

### 水群/刷屏判定

- 刷屏：同一用户在 **5 秒内**发送 **5 条**完全相同的文字（可夹杂其它内容，按相同文本计数）。
- 水群：同一用户**连续**发送 **5 条**完全相同的文字（无时间窗口，中间插一条不同内容即重置）。
- 命中后永久禁言并清理触发消息；白名单关键词、管理员、用户白名单仍跳过。

### 并发转发

- 同一用户在同一群，按消息发送时间 **2 秒内转发满 4 条**，永久禁言，并删除这几条转发。相册里的每一条单独计数。
- 编辑已有转发、频道自动同步到讨论组的消息不计数。来源关键词命中仍先永久拉黑。
- 管理员、白名单仍跳过。群内提醒与水群相同，管理员引用该提醒发送 `/un` 可解除。同一次爆发只发一条提醒。
- 开关在该机器人私聊的「检测开关」里，默认开启。主机器人和每个克隆机器人各存自己的一份，关掉一个不影响其他机器人。

### 水群/刷屏快捷解除

- 触发水群或刷屏检测后，群内会发提醒：`{用户} 触发水群检测，有问题联系管理员。`（并提示可 `/un`）。
- 管理员**引用该机器人提醒**后发送 `/un`，直接解除对应用户禁言，无需再查用户名或数字 ID。
- 引用普通用户消息时的 `/un` 与 `/unjy` 行为一致。

### 消息链路顺序（闭环）

普通群消息处理顺序：登记管理群 → 进群 → GuestBot → TG/内部管理员 → 非管 Bot → **用户白名单** → 转发来源 → 并发转发 → spoiler（含 `has_media_spoiler`）→ 已封禁补踢 → 名片（自己的/别人的/仅电话/Telegram 账号/vCard 文件一律永久拉黑）→ 文字检测（刷屏/水群/关键词/邀请链接群名）。工作群自毁只挂在机器人发送成功的回执上，不进入收消息检测链路。

### 邀请链接群名

工作群用 `/q <关键词>` 添加，`/q list` 查看和删除。只解析消息正文、说明、隐藏链接和按钮里的 `t.me/+`、`joinchat` 和公开群链接，拿群名或频道名做匹配。不看群简介，也不扫个人简介。个人主页不按这条处理。没配群名关键词时不访问链接。同一链接的群名会在进程内缓存。

关键词匹配先折叠再比：英文不区分大小写与全角，中文不区分简繁；Unicode 兼容汉字能折则折，其它形近/象形字不硬猜。启动或 `/reload` 时按同一规则合并库内重复词，保留最早一条。

封禁清理对齐官方 `banChatMember(revoke_messages=true)`，并辅以显式 `deleteMessage`；人工 `/f` `/lh` 同步开启 revoke。

同一次普通进群可能同时触发上述两个入口，`shouldProcessJoin` 以（群, 用户）为键在 `joinDedupTTL`（30 秒）内去重，避免重复封禁/广播。

### 进群检测的处置顺序（checkJoinedMember）

1. 跳过机器人账号（`IsBot`）、机器人内部管理员、白名单用户。
2. 去重：同一次进群只处置一次。
3. 已被封禁的账号再次进群：走 `BanUser` 幂等补踢，并清理进群提示消息。
4. 复用 `CheckAll`（构造仅含 `From` 的消息，无文本时只跑昵称+简介检测）：命中即封禁、删除进群提示消息、广播到工作群。
5. 俄罗斯元素硬规则（中文群）：显示名 / 用户名 / 简介含西里尔字母或俄罗斯地区名（含 🇷🇺、莫斯科、Russia 等），或客户端语言为 `ru`，或商家地址/介绍含上述元素，直接拉黑。Bot API 没有单独的「位置/关系」字段，地区只能从简介文本、商家地址和语言读取。不匹配单纯拉丁转写名（如 `Ivan`）。管理员 / 白名单仍跳过。不检查群消息正文，避免中文讨论被误杀。

### 局限

- 进群时昵称/简介干净、仅在进群后才发广告内容的账号，进群那一刻无可检测信息，仍由 `HandleMessage` 在其发消息时兜底拦截。
- chat_member 更新要求机器人为群管理员；机器人本就需要管理员权限才能封禁/删消息，因此该前提与正常运行一致。

## 消息清理策略

封禁用户时按两层清理触发消息，避免广告原文沉淀：

1. `BanChatMember(RevokeMessages=true)`：由 Telegram 服务端清空该用户在群内的全部消息。
2. 显式 `DeleteMessage(messageID)`：无条件删除本次触发检测的那条消息，作为兜底。

### 管理员消息保护

自动检测和命令清理不得删除以下身份发送的消息：

- Telegram 群主、真人管理员和管理员 Bot；
- 以群身份发言的匿名管理员；
- Bot 后台配置的管理员、作者和全局超管。

管理员列表拉取失败时采用“失败关闭”：暂时跳过该消息的自动检测，避免把身份未知的管理员误判为普通成员。管理员 Bot 若未出现在管理员列表缓存中，会通过 `GetChatMember` 单点复核。收到 `chat_member` 身份变更后立即失效管理员缓存，避免升任管理员后仍使用旧身份。

### 跨群解除拉黑

管理员在任一群回复目标消息执行 `/unlh`，或使用 `/unlh @用户名`、`/unlh 数字ID` 后：

1. 立即解除当前群拉黑；
2. 异步解除该 Bot 历史封禁记录涉及的群和当前运行期已登记的全部管理群；
3. 主 Bot 与克隆 Bot 之间同步解封，各 Bot 使用自己的存储并处理自己登记的管理群。

Telegram Bot API 不提供“列出 Bot 所在全部群”的接口，因此从未产生封禁记录、且本次进程启动后尚未收到任何消息的群无法主动发现；群一旦有消息或成员状态更新，就会进入运行期管理群列表。

### 运维要点

- 上述两种删除都要求机器人在群里具备**删除消息**管理员权限。
- 若机器人只有"封禁/限制成员"权限而无"删除消息"权限：封禁会成功，但消息不会被删除且不报错（静默失效）。出现"已拉黑但广告还在"时，优先检查该权限。
